Overview

Dizel 1.6 Flash is a decoder-only sparse mixture-of-experts model: 435.3M total parameters, 293.7M active per token, and a 2,048-token context. It is a preview. The weights and downstream benchmarks are not published.

Evaluation checkpoint. This is a pretrain snapshot, not an instruct release. Use v1.5 for the published model that runs in the app.

What is verified

At step 10,500, the held-out BPB is 1.1236 and validation loss is 3.4479. These are training-loop measurements, not downstream benchmark scores. The fixed 500-document holdout is not yet published.

What is not

There is no public benchmark table, no instruct weights, and no multimodal encoder. The preview exists to test the sparse architecture and the training recipe before a stable release.

Architecture

A decoder-only causal Transformer with pre-RMSNorm, RoPE, grouped-query attention, SwiGLU, and tied embeddings. v1.6 replaces the dense feed-forward block with a dropless top-2 mixture of experts.

token→RMSNorm→GQA→+ residual→RMSNorm→router · top-2→2 experts→+ residual

Why top-2

Every token is processed by its top two experts; no token is dropped for capacity. All four experts stay in memory even though only two fire per token. That is the trade: 435.3M parameters of capacity, 293.7M parameters of compute.

Why grouped-query attention

GQA shares K/V heads across query groups. It cuts the KV cache and memory bandwidth without collapsing to single-head MQA. v1.6 uses 12 query heads and 6 KV heads at d_model=768.

Router stability

The router is dropless. An auxiliary loss of 0.01 and a router z-loss of 0.001 encourage balanced expert use; router logits stay in float32.

Training

Pretraining runs on one T4 with an effective batch of 65,536 tokens. Every 500 steps the run validates on a fixed 500-document holdout and syncs the best checkpoint. The last verified point is step 10,500.

Limitations

  • No vision. There is no image encoder, image tokens, or multimodal projection.
  • 2,048-token context. The app does not extend the model’s window.
  • No instruct release. The preview checkpoint is for evaluation; v1.5 is the model to run.
  • No public downstream benchmarks. BPB and validation loss are training-loop measurements, not task scores.
  • No published holdout. The fixed 500-document set is named but not released, so the BPB cannot yet be independently reproduced.
