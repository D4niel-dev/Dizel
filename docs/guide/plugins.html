Docs/Controls/MCP plugins

MCP plugins

Connect tools from other programs through the Model Context Protocol. A server can expose data lookups, actions, or both; Dizel keeps direct calls separate from model-driven calls.

MCP tools are a separate trust boundary. Direct MCP calls and model MCP tools do not inherit Dizel's built-in write, edit, or delete approval rules. Connect only servers you trust and start with read-only tools.

Add a server

Desktop: open the composer's + menu → Plugins, or go to Settings → MCP. Choose Add server, configure one of the two supported transports, then save it.

TransportConfigurationUse it for
stdioCommand, one argument per line, optional environment variablesA local MCP process started by Dizel
httpHTTP or HTTPS URL, optional headersA remote Streamable HTTP MCP server

Choose Test before enabling a new server. A ready connection lists the tools it exposes. Malformed server entries are skipped rather than preventing the app from starting; legacy SSE transport is not accepted.

Terminal: run /mcp. Use Space to toggle a server, T to test, A to add, E to edit, D to delete, and Esc to close.

Connection and output limits

The desktop's Connection & limits section applies one set of preferences to every MCP server.

PreferenceRangeDefault
Connect timeout5–60 seconds15 seconds
Call timeout10–300 seconds60 seconds
Tool output cap1,000–32,000 characters6,000 characters

Retry failed calls reconnects once and retries a failed call. Auto-connect on launch starts enabled servers when the desktop app opens. The terminal applies enabled servers when it starts; use /mcp to inspect their current state.

Discover tools

Run /plugins to list configured servers, connection state, and namespaced tools such as server__tool. Server and tool selectors accept IDs or display names. A server must be connected before its tools can run.

/mcp
/plugins

The desktop Plugins runner uses the same catalog and shows each tool's arguments and result. Discovery does not enable model access: the model's tools switch is separate.

Choose a call path

CommandWhat happensModel tools required?
/plugins run <server> <tool> [json]Runs once now and prints the result.No
/plugins prompt <server> <tool> [json]Inserts a namespaced tool call into the composer for you to review and send.Yes

Optional arguments must be a JSON object. Before a model-driven call, turn on the registry with /tools tools on. Turning it off prevents model tool calls but does not prevent you from running a direct command yourself.

/plugins run <server> <tool> {"query": "release notes"}
/plugins prompt <server> <tool> {"query": "release notes"}
/tools tools on

Review inserted calls before sending: the model may follow the tool result with another request or action. The tools switch has no separate web-search toggle.

Secrets and safe use

  • Give each server only the environment variables and headers it needs. Those values stay in the local settings file and are redacted from configuration HTTP responses and exports.
  • The output cap limits how much text reaches the model; it is not a sandbox and does not make a server safe.
  • Use a dedicated, least-privilege account for servers that can change remote state. Test with a read-only operation first.
  • Do not assume Dizel's file-write approvals protect an MCP server's own mutations. Inspect the server's documentation and confirm consequential actions in its own system.
  • Settings imports leave MCP server definitions unchanged, so review existing servers separately when moving to a new machine.
