Docs/Controls/Providers

Providers

Choose where replies come from: a local Dizel checkpoint, Ollama, a hosted API, or an OpenAI-compatible endpoint. One provider is active at a time.

Local needs no API key. Dizel 1.5 checkpoints and Ollama run on your machine. Hosted and custom providers require their own key; Dizel does not provide one.

Choose a provider

Desktop: press Ctrl+,, open Chat → Provider, choose a card, then follow its setup panel. Terminal: run /provider for the picker or pass a provider name directly.

PathAvailable providersKey
LocalPublished Dizel checkpointsNo
OllamaModels installed in your Ollama serverNo
HostedOpenAI, Anthropic, Google, Groq, Mistral, xAI, AI21, Azure, Cohere, and MetaYes
CustomAny OpenAI-compatible base URLUsually
Azure is the OpenAI-compatible path. The current Azure option targets the public OpenAI endpoint; it does not configure an Azure resource name, deployment, or API version.
/provider
/provider ollama llama3.2
/model

/model opens the checkpoint picker for Local and the model picker for an API provider. You can also pass a model name, for example /model Dizel 1.5 Distill.

Hosted and custom APIs

For a hosted provider, enter its API key and an optional model ID, then choose Save key. In the terminal, the picker asks for a missing key. Prefer that prompt over putting a key directly on the command line, where shell history may retain it.

For a custom provider, enter a display name, an OpenAI-compatible base URL, the key, and an optional model ID. The base URL usually ends in /v1. Choose Save & connect; Dizel attempts to discover the endpoint's models.

In the terminal, set the custom base URL under /settings → API before selecting custom with /provider.

Protect the settings file. Keys are stored in settings.json. When the cryptography package is available, Dizel uses a machine-derived Fernet key; without it, storage falls back to reversible b64: encoding. This is not portable secret management, so do not share the file or paste key values into issues, logs, or notebooks.

Use Ollama

Start Ollama in its own terminal, then install or choose a model. The default server URL is http://localhost:11434.

ollama serve
ollama pull llama3.2

Desktop: select Ollama, adjust the URL if needed, choose Refresh, select a model, then choose Use Ollama. Terminal: use /provider ollama and select a model, or pass one as shown above.

Ollama uses its native chat API. A connection error usually means the server is not running, the URL is wrong, or the selected model is not installed.

Use a local checkpoint

Dizel 1.5 is the published, runnable model. Choose a checkpoint in the desktop model picker, or start the terminal with one explicitly:

python -m inference.tui.main \
  --checkpoint checkpoints/dizel15/dizel-v15-distill-best.pt \
  --device cuda

Use --device cpu when no compatible GPU is available. Inside the TUI, /provider local selects the local backend and /model opens checkpoint history. The checkpoint supplies the local context-window size.

Preview weights are not published. Dizel 1.6 Flash Preview and the planned 1.6 Pro track are not alternatives you can download and select today.

Context, usage, and settings

Each provider has its own context-window setting and 12-hour usage bucket, including Local. The bucket drives Dizel's usage meter and compaction policy; it is not a report of your vendor's billing or quota. For Local, the default capacity comes from the loaded checkpoint.

Settings live in inference/.dizel/settings.json by default. Set DIZEL_CONFIG_DIR to use another settings directory; chat history has a separate DIZEL_DATA_DIR setting. Changing the config directory does not move saved chats.

See Sessions & context for the difference between exact tokenizer-backed context counts and the usage meter's policy estimate.
