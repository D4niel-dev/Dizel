Modes & replies

Choose the job first, then tune how much the model reasons or writes. These controls change the prompt and generation budget; they do not switch to a different model.

Four modes, no tier selector. Fast, Planning, Coding, and Thinking work across the Dizel model families. Fast has three reply speeds; Thinking has five effort levels.

Choose a mode

In the desktop app, open the mode picker from the composer. In the terminal, run /mode for the picker or pass a mode directly. The mode applies to the next reply.

ModeUse it forWhat changes
FastDirect questions, summaries, and small editsLeads with the result and removes preamble, filler, and closing summaries. A nested speed control tunes the Fast clause and budget.
PlanningMulti-step work with constraints or tradeoffsAsks for a compact goal, steps, and main risk, then carries out the plan. /plan selects Planning automatically.
CodingRunnable implementations and debuggingPuts working code first, with imports and no placeholders, then explains only important decisions and checks.
ThinkingAmbiguous problems and careful analysisReasons inside a think block, then answers outside it. A nested effort control changes reasoning depth, sampling temperature, and budget.
 
/mode fast
/mode planning
/mode coding
/mode thinking high

Fast reply speeds

Fast mode contains Fast, Turbo, and Ultrafast. Higher settings carry a stronger brevity clause and a larger reply-budget multiplier, leaving room for the model to converge on a direct answer.

SpeedBudget factorPrompt direction
Fast1.00×Lead with the result; skip preamble and filler.
Turbo1.15×Answer promptly with short sentences and no recap.
Ultrafast1.30×Return only the direct result in as few words as correctness allows.
Speed is a response style, not a latency benchmark. These settings do not change temperature or decoding parameters, and Dizel publishes no measured wall-clock speedup for them.

Desktop: open Fast mode, then use its nested Reply speed slider. Terminal: pass the speed after the mode.

/mode fast turbo
/mode fast ultrafast

Thinking effort

Thinking mode has five effort levels. Higher levels ask for more decomposition and checking, adjust the mode's sampling temperature, and increase its budget multiplier.

LabelCommand valueBudget factorReasoning direction
Lowlow0.75×Think briefly, then answer directly.
Mediummedium1.00×Check assumptions and edge cases.
Highhigh1.15×Compare approaches and verify the answer.
X-Highxhigh1.30×Decompose, weigh alternatives, and review failure modes.
Maxdeep1.40×Explore several routes and stress-test the answer.

Max is the current label for the deep effort; it is not a fifth mode. /mode deep remains a shortcut for Thinking at Max.

/mode thinking low
/mode thinking xhigh
/mode deep

Response length

Response length is independent of mode. It scales the task budget and, for Short and Detailed, adds an explicit clause to the prompt. Normal adds no clause.

LengthBudget factorPrompt clause
Short0.60×Answer in the fewest useful words; no examples or recap unless asked.
Normal1.00×None — the default prompt stays unchanged.
Detailed1.50×Explain reasoning and edge cases, with examples and structure where useful.

Desktop: open the composer's + menu → Reply, or use Settings → Chat. Terminal: use /verbosity; /length is an alias. The choice is saved and restored on the next launch.

/verbosity
/verbosity short
/verbosity detailed
/verbosity normal
Factors are not final token counts. The allocator also considers the task, input length, remaining context, and any hard output limit before clamping the reply budget.
